This section covers `Azure IoT Edge`, the Azure service used to run cloud-managed workloads directly on edge devices.

### *Azure IoT Edge*

`Azure IoT Edge` extends Azure IoT capabilities from the cloud down to local devices and edge gateways.

Instead of sending every operation to the cloud, IoT Edge allows workloads to run directly near the data source.

This is useful when you need:

- local processing
- reduced latency
- offline or intermittent connectivity support
- cloud-managed workloads at the edge

<Aside type="note">
`IoT Edge` is especially useful when devices must continue operating even when cloud connectivity is limited or when data should be filtered before being sent to Azure.
</Aside>

### *How It Works*

IoT Edge runs containerized modules on an edge device.

These modules can perform:

- local data processing
- filtering
- transformation
- AI inference
- protocol translation

The device is still connected to Azure for management and monitoring through the IoT platform.

### *Typical Flow*

<Steps>
1. Register the edge device with Azure IoT.
2. Install the IoT Edge runtime on the device.
3. Deploy one or more modules from Azure.
4. The modules process data locally on the device.
5. The edge device sends selected telemetry or results back to the cloud.
</Steps>

### *IoT Edge Vs. IoT Hub*

| Service | Best For |
| --- | --- |
| `Azure IoT Hub` | Secure communication and management of devices from the cloud |
| `Azure IoT Edge` | Running workloads and intelligence directly on edge devices |

`IoT Hub` manages communication.

`IoT Edge` extends cloud logic and application modules to local environments.

### *Summary*

- `Azure IoT Edge` runs Azure-managed workloads on edge devices
- It supports local processing, filtering, and AI inference
- It is useful when latency, bandwidth, or offline operation matter
- It works through containerized modules on edge devices
- It complements `IoT Hub` by extending IoT architecture beyond the cloud
