This section covers `Azure SQL Database`, the managed relational database service in Azure.

### *Azure SQL Database*

`Azure SQL Database` is a fully managed `Platform as a Service (PaaS)` relational database built on the Microsoft SQL Server engine.

It is designed for applications that need:

- structured relational data
- SQL queries
- managed backups
- high availability
- reduced infrastructure management

With Azure SQL Database, Microsoft manages the operating system, patching, backups, and much of the underlying availability platform.

<Aside type="note">
`Azure SQL Database` is often chosen when teams want SQL Server compatibility without managing a full virtual machine or database server installation.
</Aside>

### *Deployment Models*

Azure SQL offers different deployment options depending on scope and isolation needs.

| Model | Best For |
| --- | --- |
| Single Database | One isolated application database |
| Elastic Pool | Multiple databases that share compute resources |
| Managed Instance | Higher SQL Server compatibility for migration scenarios |

### *How It Works*

<Steps>
1. Create a logical SQL server in Azure.
2. Create one or more `Azure SQL Databases`.
3. Configure networking, authentication, and firewall rules.
4. Connect applications using SQL clients or drivers.
5. Azure manages backups, updates, and platform availability.
</Steps>

### *Azure SQL Database Vs. SQL Server On A VM*

| Service | Best For |
| --- | --- |
| `Azure SQL Database` | Managed relational database with reduced operations |
| `SQL Server on Azure VM` | Full operating system and SQL Server control |

`Azure SQL Database` is the better option when you want less operational overhead.

A VM-based SQL Server is more appropriate when you need deep OS-level or instance-level customization.

### *Typical Features*

### *Summary*

- `Azure SQL Database` is a managed relational database service
