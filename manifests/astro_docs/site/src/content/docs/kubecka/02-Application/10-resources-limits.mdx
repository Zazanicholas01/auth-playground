### *Come funziona*

<Steps>
1. Kubernetes legge le `requests` del Pod.
2. Lo `Scheduler` sceglie un nodo con risorse sufficienti.
3. Il Pod viene avviato sul nodo selezionato.
4. Durante l'esecuzione, il kernel applica i `limits`.
</Steps>

### *Scenari*

| Configurazione | Comportamento | Nota |
| --- | --- | --- |
| No Requests / No Limits | Nessuna garanzia e nessun tetto | Puo` consumare tutto il nodo |
| No Requests / Limits | La `request` diventa uguale al `limit` | Piu` sicuro ma meno flessibile |
| Requests / Limits | Minimo garantito e tetto massimo | Scenario piu` comune |
| Requests / No Limits | Minimo garantito senza tetto massimo | Può creare instabilità |
