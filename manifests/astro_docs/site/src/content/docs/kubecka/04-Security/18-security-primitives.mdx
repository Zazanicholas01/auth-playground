### *Securing Hosts*

- Usa sistemi operativi minimali
- Limita o disabilita l'accesso `SSH`

### *Securing the API Server*

- Non esporre l'`API Server` su Internet

### *Authentication e Authorization*

| Livello | Scopo | Esempi |
| --- | --- | --- |
| Authentication | Identificare chi fa la richiesta | `X.509`, `OIDC`, `ServiceAccount` |
| Authorization | Stabilire cosa puo` fare | `RBAC`, `Role`, `ClusterRole`, `RoleBinding` |

<Aside type="note">
Segui sempre il principio del `Least Privilege` e `Zero Trust`: concedi solo i permessi minimi necessari.
</Aside>

### *TLS Certificates*

<Steps>
1. Kubernetes usa una CA interna.
2. I componenti comunicano tramite `TLS`.
3. `API Server`, `etcd`, `Scheduler` e `Kubelet` usano certificati.
4. Per le applicazioni, puoi usare `cert-manager`.
</Steps>

### *Network Policies*

Le `Network Policies` limitano il traffico tra Pod.

- controllano `Ingress`
- controllano `Egress`
- permettono isolamento tra namespace e workload

<Aside type="caution">
La best practice è applicare una policy `Default Deny` e aprire solo il traffico necessario.
</Aside>
