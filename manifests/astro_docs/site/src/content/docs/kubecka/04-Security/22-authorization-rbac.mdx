L'`Authorization` decide se un'identità autenticata puo` eseguire un'azione su una risorsa.

### *Principio base*

- Kubernetes non concede permessi di default.
- I permessi vanno assegnati esplicitamente.
- La best practice è il `Least Privilege`.

### *Come funziona*

<Steps>
1. L'utente o il `ServiceAccount` viene autenticato.
2. Kubernetes controlla i `Role` o `ClusterRole`.
3. Verifica i `Binding` associati.
4. Se una regola lo consente, l'azione viene autorizzata.
</Steps>

### *Anatomia di una regola*

| Campo | Significato |
| --- | --- |
| `apiGroups` | Gruppo API della risorsa |
| `resources` | Risorse su cui agire |
| `verbs` | Azioni consentite |

### *Verifica dei permessi*

| Comando | Scopo |
| --- | --- |
| `kubectl auth can-i create pods` | Verifica se puoi creare Pod |
| `kubectl auth can-i get secrets --as luca@example.com` | Verifica i permessi di un utente |
| `kubectl auth can-i delete svc --as system:serviceaccount:dev:deploy-bot` | Verifica i permessi di un ServiceAccount |
